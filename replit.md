# Plunderverse - Compressed Technical Specification

## Overview
"Plunderverse" is a 3D space outlaw game inspired by Firefly, built with React, Three.js, and Express. Set in a bankrupt solar system in 2149, players take on the roles of smugglers and space outlaws. The game centers around dynamic gameplay loops including trade and survival, mission and story progression, and combat and notoriety management, all within a procedurally generated, economically driven solar system. The goal is to deliver a comprehensive, highly replayable outlaw experience in space with a rich narrative and emergent gameplay.

## User Preferences
Preferred communication style: Simple, everyday language.

### UI Design Guidelines
- **Action Buttons**: Use icon-only design with hover-over tooltips for better space efficiency
- **Button Style**: `bg-gray-900/90 hover:bg-cyan-600/90 text-cyan-400 hover:text-white w-10 h-10 rounded-lg border border-cyan-400/50 hover:border-cyan-400 transition-all backdrop-blur-sm flex items-center justify-center`
- **Icon Size**: Use `text-xl` for icon size within buttons
- **Tooltip**: Always include descriptive `title` attribute for accessibility
- **Consistency**: All new UI action items should follow this pattern for uniformity and better layout

## System Architecture
The project utilizes a client-server architecture with React 18.3.1, Three.js (React Three Fiber 8.x), and Zustand 5.0 for the frontend, and Express 4.x with PostgreSQL (Neon-backed) and Drizzle ORM for the backend. Development is managed with Vite 6.x and TypeScript 5.7, while styling is handled by TailwindCSS 3.x with Radix UI components.

### Core Gameplay Loops
The game features three primary loops:
1.  **Trade & Survive**: Involves mining resources, dynamic trading across stations with fluctuating prices, and continuous resource management (fuel, hull, oxygen, crew wages). Economic pressure is persistent, affecting equipment degradation and faction reputation.
2.  **Mission & Story**: Players discover missions on boards, with access gated by reputation. Missions include delivery, combat, exploration, and a multi-act story with branching choices affecting karma, faction relations, and leading to five distinct endings.
3.  **Combat & Heat**: Combat involves engagement with various enemy types, turn-based positioning, and damage calculation. Heat is generated by illegal activities, leading to increasing notoriety, aggressive patrols, and "shoot on sight" orders at maximum levels.

### Item Catalog & Schemas
The game includes a diverse catalog of trade goods, ship modules, and special items. Data is structured using TypeScript interfaces for `PlayerProfile`, `Ship`, `Mission`, `CrewMember`, and `StarNode`, ensuring robust data management for all game entities and their properties.

### UI/UX Decisions
The UI features distinct desktop and mobile layouts, prioritizing responsiveness.
-   **Desktop**: A three-panel layout with a central 3D viewport, sidebars for navigation and actions, and a bottom control bar.
-   **Mobile**: A touch-optimized layout with a header, 3D viewport, virtual joystick, action bar, and slide-in overlay panels.
-   **Color Palette**: Primarily uses deep space darks with vibrant cyan accents for interactive elements and status indicators. Faction-specific colors are also defined.
-   **Components**: Standardized button, panel, and HUD element styles are defined with specific CSS properties and animation specifications for transitions, hover states, and combat feedback.
-   **Accessibility**: Includes colorblind modes, font scaling, high contrast, motion reduction, screen reader support, subtitles, visual sound indicators, rebindable controls, and auto-aim assistance.

### Game Balance Parameters
Detailed parameters are set for economy (starting conditions, operating costs, profit margins), combat (weapon damage, enemy scaling, difficulty multipliers), mission rewards, reputation thresholds and decay, heat system thresholds, and crew loyalty modifiers and effects. These are designed to ensure a challenging yet fair progression and diverse gameplay outcomes.

### System Design
The application structure is hierarchical, centering around an `AuthProvider` managing `LoginScreen` and `GameContainer`. The `GameContainer` integrates a `ThreeCanvas` (for 3D rendering), a `UILayer`, and an `AudioSystem`. State management is handled via Zustand stores for player, ship, economy, combat, and mission data.
-   **Render Pipeline**: Utilizes Three.js with specific lighting, camera controls, object hierarchies (planets, asteroids, ships), and post-processing effects (Bloom, Chromatic Aberration).
-   **Performance Optimizations**: Implements object pooling for projectiles, particles, and enemies; an LOD system for planets and ships; and efficient texture management (lazy loading, compression, mipmapping) to maintain target frame rates (60 FPS desktop, 30 FPS mobile).
-   **Save System**: Game state is saved into a structured JSON format, including player, ship, mission, and world data, with multiple save slots and a backup strategy.

## External Dependencies

-   **Frontend Framework**: React 18.3.1
-   **3D Graphics Library**: Three.js (via React Three Fiber 8.x)
-   **State Management**: Zustand 5.0
-   **Backend Framework**: Express 4.x
-   **Database**: PostgreSQL (Neon-backed)
-   **ORM**: Drizzle ORM
-   **Build Tool**: Vite 6.x
-   **Language**: TypeScript 5.7
-   **Styling**: TailwindCSS 3.x with Radix UI components
-   **Authentication**: Session-based authentication stored in PostgreSQL.
-   **Network Protocol**: WebSocket for real-time multiplayer communication, with server-authoritative state, input validation, and rate limiting for anti-cheat measures.
